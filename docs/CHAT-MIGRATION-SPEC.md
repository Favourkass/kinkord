## Runtime contracts

These contracts are part of the chat migration and must remain aligned with the
API and `chat_demo` client.

### Socket.IO message acknowledgements

The `message:send` handler receives only the connected socket and message body.
The acknowledgement callback is supplied by Socket.IO to Nest's event adapter;
it must not be decorated as `@ConnectedSocket()` or accepted as a handler
parameter. The handler returns the acknowledgement value and Nest forwards it
to the sender's callback.

Successful acknowledgement:

```json
{ "ok": true, "data": { "id": "...", "conversationId": "..." } }
```

Rejected or failed acknowledgement:

```json
{ "ok": false, "error": "not_a_participant" }
```

The message is persisted and broadcast before the successful acknowledgement
is returned. Errors must be returned through the envelope rather than thrown
after persistence, so the sender callback always fires.

### Starting a direct message

`POST /conversations/dm` accepts `{ "userId": "<other-user-id>" }`.

- The authenticated user may not target their own id. This returns `400` with
	`Cannot DM yourself`.
- A target id that is not present in Better Auth's `user` table returns `404`
	with `User not found`; no conversation is created.
- The current schema has no block list, privacy setting, or message-request
	policy. Until one is introduced, an existing Better Auth user is considered
	messageable. Any future restriction belongs in the service before the DM is
	inserted.

### Participant avatars

Conversation participants expose `avatarUrl`, not Better Auth's `user.image`.
The API joins the `profile` row, reads `profile.avatar_key`, and presigns that
object-storage key through `StorageService.presignDownload`. A missing profile
or avatar key produces `avatarUrl: null`; raw storage keys and Better Auth image
values must not be sent as chat avatar URLs.



## Tables

### `users` 

Legacy chat identity table.

| Column | Type | Constraints | Purpose |
| --- | --- | --- | --- |
| `id` | `uuid` | Primary key, generated by `gen_random_uuid()` | User identifier |
| `username` | `text` | Required, unique | Public handle |
| `display_name` | `text` | Required | Display name |
| `avatar_url` | `text` | Nullable | Legacy avatar URL; not used by current chat |
| `created_at` | `timestamptz` | Required, defaults to `now()` | Creation timestamp |

The current application no longer exposes this table as its authenticated identity source. Do not include it in the new design unless a separate legacy chat identity table is intentional. Current chat users are Better Auth `user` records with text ids; public avatars are stored as keys in `profile.avatar_key`.

### `conversations`

Represents a direct-message or group conversation.

| Column | Type | Constraints | Purpose |
| --- | --- | --- | --- |
| `id` | `uuid` in both historical SQL files | Primary key, generated by `gen_random_uuid()` | Conversation identifier |
| `type` | `text` | Required, defaults to `dm` | Conversation type |
| `dm_key` | `text` | Nullable, unique | Canonical key for one direct-message pair |
| `title` | `text` | Nullable | Optional group title |
| `created_at` | `timestamptz` | Required, defaults to `now()` | Creation timestamp |
| `last_message_at` | `timestamptz` | Nullable | Sorting and preview timestamp |

Recommended current design: retain UUID conversation IDs unless the application contract requires text IDs.

### `conversation_participants`

Join table connecting users to conversations and storing read state.

| Column | Type in historical SQL | Constraints | Purpose |
| --- | --- | --- | --- |
| `conversation_id` | `uuid` | Required, foreign key to `conversations.id`, cascade delete | Conversation membership |
| `user_id` | `uuid` | Required, foreign key to `users.id` in `0000_init.sql`, or `user.id` in `0001_chat.sql` | Member identity |
| `joined_at` | `timestamptz` | Required, defaults to `now()` | Membership start |
| `last_read_message_id` | `uuid` | Nullable | Most recent message marked read |

Primary key: (`conversation_id`, `user_id`).

Index: `cp_user_idx` on `user_id`.

### `messages`

Stores messages sent inside conversations.

| Column | Type in historical SQL | Constraints | Purpose |
| --- | --- | --- | --- |
| `id` | `uuid` | Primary key, generated by `gen_random_uuid()` | Message identifier |
| `conversation_id` | `uuid` | Required, foreign key to `conversations.id`, cascade delete | Owning conversation |
| `sender_id` | `uuid` | Required, foreign key to `users.id` or `user.id` depending on migration | Sending user |
| `body` | `text` | Nullable | Text body |
| `client_id` | `text` | Nullable | Client-generated idempotency key |
| `created_at` | `timestamptz` | Required, defaults to `now()` | Message timestamp |

Index: `messages_conv_created_idx` on (`conversation_id`, `created_at`).

Partial unique index: `messages_sender_client_uidx` on (`sender_id`, `client_id`) where `client_id IS NOT NULL`.

### `attachments`

Stores metadata for files uploaded to S3-compatible storage.

| Column | Type in historical SQL | Constraints | Purpose |
| --- | --- | --- | --- |
| `id` | `uuid` | Primary key, generated by `gen_random_uuid()` | Attachment identifier |
| `message_id` | `uuid` | Nullable, foreign key to `messages.id`, cascade delete | Associated message |
| `uploader_id` | `uuid` | Required, foreign key to `users.id` or `user.id` depending on migration | Uploading user |
| `key` | `text` | Required | Object-storage key |
| `filename` | `text` | Required | Original filename |
| `mime` | `text` | Required | MIME type |
| `size` | `bigint` | Required | File size in bytes |
| `width` | `integer` | Nullable | Image width when available |
| `height` | `integer` | Nullable | Image height when available |
| `created_at` | `timestamptz` | Required, defaults to `now()` | Upload timestamp |

Index: `attachments_message_idx` on `message_id`.
