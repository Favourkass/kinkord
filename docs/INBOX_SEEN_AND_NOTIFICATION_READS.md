# Inbox attention and viewed notifications

- Apply `apps/api/drizzle/0034_inbox_seen.sql` through the normal migration runner before deploying the new API.
- `POST /chat/inbox-seen` stores the authenticated member's inbox-entry time monotonically. `/chat/unread-count` is the navigation attention badge: unread incoming messages newer than that time. Conversation read receipts, inbox filters and each row's unread count remain independent.
- Opening Messages renders its navigation badge as zero immediately. Inbox entry, foreground return and reconnection persist attention to the backend. Other open devices receive `inbox_seen`; missed events recover through polling/focus refresh.
- Only `POST /chat/conversations/:id/read` advances that conversation's read receipt. It also broadcasts to the member's other devices, even if its notification was already read.
- Notifications now include message alerts in the list and unread category totals. Reading a message alert never calls the chat read endpoint and accepting friendship remains a separate action.
- At least half of a notification row must be visible in a foreground page for 250ms; covered rows and unloaded pages do not count. Visible rows are batched, at most 50 per request, through authenticated `POST /notifications/read-viewed`. Each snapshot carries its ID, activity timestamp and count. The API matches ownership and that exact version, leaving a newer message bump unread. Offline failures retry while the row stays visible.
- `GET /notifications/app-badge-count` combines non-message notification unread rows with the message navigation badge, avoiding duplicate message alerts. The page and service worker use this authoritative total with `setAppBadge`/`clearAppBadge`, when available. The worker persists only the endpoint configuration, refreshes counts on push, and clears it on logout. Android launchers/browsers ultimately control badge support. Closed devices reconcile on their next push or foreground wake; open devices receive realtime read updates with polling fallback.

Validation: unit tests cover separate counts, authenticated version snapshots, viewing/visibility/occlusion, automatic reads across notification categories, stale events and supported/unsupported app badges. A local PostgreSQL integration check verified persistent inbox state, unchanged filters and conversation unread totals, new arrivals, alert reads, ownership isolation and no duplicate launcher counts, with all fixture data rolled back.
